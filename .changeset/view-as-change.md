View the library as a change. On Studio Tokens, Components and Quality, a "Viewing: Latest library" Select in the top bar lists the open changes with their status; picking one shows the page as it would be with that change applied, read only, with a persistent banner ("Viewing the library as Brighter primary action. Nothing is saved.") and the ways out: back to the latest library, open the change, and on Tokens "Edit tokens in this change". Tokens reads the change's token files and lists the tokens it changes first, marked "Changed in this change" with their latest library value on hover. Components paints its previews with the change's tokens and marks the components that look different or whose guidance the change edits. Quality never shows the latest library's numbers for a change: it says the change's quality is in its checks and links there. The address holds the view (`?change=N`); editing a change is `?change=N&edit=1`, so the two share one model, and links between these pages keep the view. Reads stay anonymous-safe: one GitHub read of the change's file list, then only the files it changed, kept in the browser per version. This replaces the branch picker StudioHeader carried but never showed.
