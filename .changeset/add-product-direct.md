Add a product, v3: one dialog, and the product is in the team at once. The dialog lists the products Bridge found on GitHub that the team does not have yet, one row each with Add, with "Not in the list? Find it on GitHub", "Give designers their own copy", Cancel and "Start a new product". When Bridge finds none it opens straight on the name and Create product, with "Its code is already on GitHub? Find it there". Add and Create product no longer wait for an approval nobody could give: Bridge checks on its server that the person is an admin or a lead of the team, validates the one new product, and writes it straight to the team's settings (`POST /api/ship` with `action: "add-product"`, the only code path that uses the Bridge app's bypass of the library's main ruleset, one file only). The dialog then closes and opens the product's page, already in the side nav, without waiting for a new build or a cache to turn. Anyone else reads why on the product's row. On a library where Bridge may not write directly (an older setup), it goes to review as before and the dialog says so plainly. Bridge's own designers' copies are never offered as products: the copies Bridge makes are now marked (a GitHub topic and their description), and copies listed in the team's settings or named after a product next to it are left out. The "Show its previews" step left the dialog; the product's page holds the way to its previews.
