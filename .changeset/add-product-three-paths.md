Add a product starts from one question, "Where does it start from?", with three equal cards: "Its code is on GitHub" (recommended), "Only its address" and "It's a new product". Details come only after a choice, and every next step has Back. Its code on GitHub keeps today's list with Add, and when Bridge sees nothing new it says so with Find it on GitHub as the one primary. Only its address is for a product whose code the design team cannot reach: its name and its address (a bare domain or an https link), then Bridge starts the design team's own code for it from the product starter with the library and keeps the address in the new optional `products[].address` (an https origin, checked by `productProblems`, the JSON schema and, strictly, by the server that adds products). Start an exploration offers an optional "Start from a page" for such a product, limited to pages of its own site: the page is kept on the exploration (`startPage`) and the line handed to Claude says to open it in the browser, rebuild it with only the library's components and tokens, never the site's own styles or files, then explore the change. `bridge_continue_exploration` returns `startFrom` with the same brief. Done exploring on such a product sends the developers a task with the preview, the page as it is today and what changes, never code to take.
