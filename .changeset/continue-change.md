Continue a change. In Studio Tokens, a designer adds more token edits to a change already in review instead of opening a new one, like "Add to open pull request" in the Figma plugin. The send dialog asks where the edits go (a DS RadioGroup): their own most recent token change is the default, "Start a new change" the alternative, and changes someone else opened are offered to people with write access but never picked for them. A change page has "Edit tokens in this change": it opens the token editor scoped to that change, with its values and a persistent banner ("Editing: Darker default background. Your edits are added to this change.") and a way back; that draft is kept apart from the local draft. Saving rereads the change and runs the same 3-way token diff as the plugin: tokens only the change moved stay as they are, and a token edited in both stops the save with a plain message and a link to the conflict flow, so nothing is overwritten. The commit goes on top of the change's current head as a fast-forward only update, the changeset keeps listing every token, and a comment lists what was added. Only open token changes (not explorations, brands or docs) take edits, and only from their author or someone with write access. The Changes draft strip says where the draft goes, and a change page says when GitHub dismissed an approval.
