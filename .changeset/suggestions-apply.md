Applying a suggestion on the code a developer has now. `planSuggestionApply` (in `@bridge-ds/core/node` for now, pure logic over a small workspace adapter) refuses unsafe paths, guardrails, symlinks and a payload edited by hand before reading anything, checks the approvals of the owners on the current payload sha, then classifies every change against the current tree: token edits re-applied with `applyTokenEdits` on the current tokens (already applied, apply, or a conflict when the value moved since), files by git blob sha with a 3-way merge when both sides moved, docs field by field, component specs with their brief. It re-runs validation, contrast and the tier on the result and stops when the tier went up or a contrast pair that passes today would fail. Re-running on a tree that has the change is a no-op. `applySuggestionLocally` writes the result as one commit on a new local branch (default, nothing pushed, the branch reused when it already has the change), into the working tree (refused over uncommitted changes), or as a `git format-patch` text, 3-way merges with `git merge-file`, and returns the applied record comment for the caller to post. The suggestion issue's "How to apply" now names Claude Code with the Bridge MCP server and its one-time install command (`bridgeMcpInstallCommand`).
