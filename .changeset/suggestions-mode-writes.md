Suggestions, mode-aware writes: the four places core writes code take a `mode` (`"suggest"` or `"direct"`, from `changesMode(config)`). Without it they behave exactly as before (direct). In suggest mode they file a suggestion issue (`bridge.suggestion/1`) through `createSuggestionOnGitHub` and never create a branch, a commit or a pull request. `suggestTokenProposalOnGitHub` (next to `writeTokenProposalOnGitHub`) files a planned token change: the exact edits, the changeset, the checks and the same tier labels; `tokenSuggestionPayload` builds its payload, and `TokenProposalPlan` now carries its `edits`. `openLibraryBranchOnGitHub({ mode })`: a token piece becomes a suggestion (its `writeTokens` callback gets `{ mode }` and may return `suggestTokenProposalOnGitHub`'s result), a variant a component request (`libraryBranchPlan(..., { mode })`), the result status is `"suggested"`, and a refused product branch record is a warning instead of an error. `LibraryLink.kind` gains `"suggestion"`, `linkStatus` maps every suggestion status (new `"outdated"` link status), `libraryPreviewState` and `linkedLibraryBranchOnGitHub` read suggestion links. `openComponentPushOnGitHub({ mode })`: an exact token swap goes through `writeTokens` (which now gets `mode` and the Figma link), a code change becomes a component spec suggestion (`componentSpecSuggestionPayload`, spec inline, labelled from Figma and waiting for Claude); the result has status `"suggested"` and `suggestion: { route, number, url }`. `figmaDraftBrief` has a suggestion form. `proposeDocsOnGitHub({ mode })` files a docs suggestion with the cleaned docs and the patch changeset (`docsSuggestionPayload`); its results now carry `status` (`"opened"`, `"continued"` or `"suggested"`).
